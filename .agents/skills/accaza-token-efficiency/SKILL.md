# Accaza token efficiency

Apply the root Output and Token Efficiency rules without weakening required reviews, verification, financial controls, security, or POS continuity.

- Start with the relevant file map and targeted `rg` searches. Read complete selected instructions, but only relevant source sections. Batch independent reads; keep dependent actions sequential.
- Reuse findings verified in this task. Refresh facts that can drift: branch/PR state, deployments, live balances, permissions, and usage.
- Delegate distinct questions with task scope, file ownership, evidence needed, and a concise result contract. Supply focused context; reuse existing specialists for follow-ups. Parallel agents save time, not necessarily tokens.
- Summarize passing output. Preserve failure details and reproducible commands/evidence. Avoid frequent unchanged polling.
- Use targeted checks while developing; run required full gates at the appropriate checkpoint. Re-run after relevant changes or failures.
- Handoff: outcome, delivery state, material risks, verification, next action, and required exact commands. Preserve complete code/artifacts when requested.

Do not promise measured token savings without usage evidence. `full-output-enforcement` is for explicitly exhaustive output, not default efficiency.
